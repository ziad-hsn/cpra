A permanent proven rejection terminates recovery independently of the attempt ceiling. Unknown outcomes still hold and cannot trigger another recovery. |
| Both macOS jobs | A launchd rendering fixture assumed the service account already existed on a clean runner. | Render using the existing native test account. Production service-account validation is unchanged. |
| macOS arm64 | A fixture required a large truncated file to allocate fewer bytes than its apparent length. | Compare reported allocation with native filesystem blocks for both short and extended files. Sparse allocation is measured, not assumed. |
| Both Windows jobs | A failed catalog replacement was required to wrap the Unix `os.LinkError` type. | Require the native permission failure and the deliberately obstructed destination; retain storage-unavailable and no-publication assertions. |
| Both Windows jobs | A GC checkpoint fixture used immediate path disappearance to detect unlink, while Windows defers removal until native handles close. | Cancel at the mandatory post-unlink checkpoint; assert path removal after the step releases its handles. |
| Both Windows jobs | Two missing-history fixtures attempted to rename a live, mapped bbolt file. | Close, rename and reopen the test segment under the history mutex. Keep a live database handle while leaving the catalog's original path missing. |

## Follow-up on the repaired commit

The private module consumer verification passed on the clean repair commit
`4010de73f22d4fdf4cc4b497eae4460c2591467b` with both Go 1.26.10 and 1.27.3.
The retained reports are `ci2-sdk-consumer-minimum-report.json` and
`ci2-sdk-consumer-release-report.json`. Each verifies the downloaded archive
contents, source-consumer checksums, excluded APIs, package documentation and
examples with `GOWORK=off` and no local replacement. This is private archive
verification, not evidence of public module availability.

The [workflow rerun on that commit](https://github.com/ziad-hsn/cpra/actions/runs/41316180894)
passed both complete SDK jobs. The container/chart job passed all 718 release
tests, then reached a previously hidden ShellCheck failure: three intentional
empty variable assignments used the ambiguous `NAME= command` spelling.
Explicit `NAME='' command` spelling preserves the fixture compiler PATH
selection and the security tool's cleared Go flags. The corrected workflows
pass the pinned actionlint with ShellCheck 0.9.0 enabled (`ci2-actionlint-1`),
and a separate reviewer confirmed that these three edits preserve behavior.

Native and browser results still belong to their actual completed workflow
jobs. The full workflow on the follow-up commit remains required; changing
workflow syntax is not permission to bypass any check.

That rerun completed with nine successful jobs: both SDKs, both A2A compilers,
both Linux native targets, both macOS native targets and documentation. The
remaining failures reached code that the earlier failures had prevented from
running:

- Both Go jobs found three cursor fixtures that treated inactive-view
  reclamation as a quota violation and two availability fixtures without the
  required controller acknowledgment/catalog identity. The fixtures now test
  protected active readers, bounded inactive reclamation, expired continuation,
  and the unavailable state before acknowledgment. Production quota and owner
  checks are unchanged.
- Both Windows jobs passed the repaired application persistence tests and then
  failed the worker's ownership check. New worker objects supplied a DACL but
  no explicit owner. Windows may select a token's default owner rather than its
  process-user SID. New directories, journal files and conversion backups now
  select that user explicitly, retaining the user/SYSTEM-only protected DACL.
  Existing keys and journals are still validated without changing their
  security. This follows Microsoft's [new-object ownership contract](https://learn.microsoft.com/en-us/windows/win32/secauthz/owner-of-a-new-object).
- The browser campaign's Go command failed after audit and accessibility
  passed, but its public summary did not identify a test. All ten required
  scenarios subsequently passed locally with the pinned compiler, Node and
  Playwright Chromium build 1194. The CI cause remains unreproduced. Public
  summaries now include only failing test/package names selected from the
  required-test inventory; raw logs and screenshots remain private.
