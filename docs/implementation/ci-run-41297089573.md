## Confirmed failures and repairs

| Checks | Cause | Repair |
|---|---|---|
| Both Go jobs | `make check` rejected formatting in `internal/persistence/recovery_rules.go`. | Apply `gofmt`; no behavior change. |
| Both SDK jobs | Source consumers still recorded hashes for older, unpublished SDK and worker archives at the candidate version. | Recreate the candidate archives using the existing `golang.org/x/mod/zip` tool and update the four consumer hash rows. Keep checksum verification enabled. No module tags are published. |
| Container/chart contracts | A real Go-event parser regression ran using the runner's Go 1.24 compiler against a Go 1.26.10 fixture. | Install the checksum-pinned release compiler before the tests. A workflow regression requires that ordering. |
| Dashboard | The audit rejected Vite 6.4.4 and vulnerable Minimatch dependencies. Type checking, lint and tests had passed. | Use Vite 6.4.5 and the ESLint 10-compatible toolchain. Restrict the Minimatch override to modern consumers and select 11.0.3. Preserve the existing two Hooks rules and zero-warning policy. |
| Both A2A jobs | The escalation test expected an obsolete seven-field failure payload and treated a permanent rejection as nonterminal when attempts remained. | Assert the eight-field payload, `permanent_rejection`, the original completion timestamp and one recovery invocation. A permanent proven rejection terminates recovery independently of the attempt ceiling. Unknown outcomes still hold and cannot trigger another recovery. |
| Both macOS jobs | A launchd rendering fixture assumed the service account already existed on a clean runner. | Render using the existing native test account. Production service-account validation is unchanged. |
| macOS arm64 | A fixture required a large truncated file to allocate fewer bytes than its apparent length. | Compare reported allocation with native filesystem blocks for both short and extended files. Sparse allocation is measured, not assumed. |
| Both Windows jobs | A failed catalog replacement was required to wrap the Unix `os.LinkError` type. | Require the native permission failure and the deliberately obstructed destination; retain storage-unavailable and no-publication assertions. |
| Both Windows jobs | A GC checkpoint fixture used immediate path disappearance to detect unlink, while Windows defers removal until native handles close. | Cancel at the mandatory post-unlink checkpoint; assert path removal after the step releases its handles. |
| Both Windows jobs | Two missing-history fixtures attempted to rename a live, mapped bbolt file. | Close, rename and reopen the test segment under the history mutex. Keep a live database handle while leaving the catalog's original path missing. |

The Linux amd64/arm64 native jobs and documentation job passed in the reported
run. No failing check is disabled, skipped or given a longer timeout by these
repairs. No production effect classifier, storage durability setting or
authentication rule changes.

The dependency fixes follow the published
[Vite advisory](https://github.com/advisories/GHSA-8g5g-mxqh-grgj) and
[Minimatch advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249).
The ESLint upgrade removes old Minimatch 3 consumers rather than forcing the
incompatible modern API into that dependency chain.
